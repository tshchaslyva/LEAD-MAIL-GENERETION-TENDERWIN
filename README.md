## 1. Що це за інструмент

Шукає відхилення учасників у Prozorro за поточну добу, складає один перший
лист на компанію, робить робочу картку закупівлі, а з версії 1.3.0 — ще й
**службову картку відхилення з протоколом рішення замовника**. З версії
1.4.0 картка і протокол лягають у `Мій диск/0 Cases/<ID закупівлі> <ЄДРПОУ>`
(на компʼютері `G:\Мій диск\0 Cases`).

**Чотири гарантії, закладені в код:**

1. У розсилку потрапляють лише події вікна прогону.
2. Одна компанія — один перший лист. Назавжди.
3. Жодного шляху доставки клієнту в коді немає: лише `TEST_RECIPIENTS`.
   Це перевіряє тригер бази, а не лише код.
4. Завантажуються **лише документи самого рішення** замовника. Документи
   пропозиції і тендерна документація — ні.

## 3. Порядок запуску в Colab

1. Чотири файли з розділу 2.1 — у теку `TenderWin` на Диску.
2. Ноутбук — туди ж, відкрити в Colab.
3. Клітинки згори вниз: 1 → 2 → 3 → 4 → 5 → 6 (сухий прогін) → 7 (відправка).
4. Перед відправкою прочитати кілька листів у `vyhid_lystiv/eml` (поруч із
   кожним лежить `.html` — лист очима клієнта).
5. Клітинка 8 (`M.kartky`) потрібна лише тоді, коли крок карток обірвався
   або треба зібрати картки за інший день.

**Команди:**

```
M.setup(DYSK)                      база, токен, перевірки — раз за сеанс
M.go(dysk=DYSK)                    сухий прогін: пошук, листи, картки
M.kartky(dysk=DYSK)                службові картки ще раз
M.kartky(day="2026-10-02", …)      картки за конкретний день
M.send(dysk=DYSK)                  відправка на ваші тестові скриньки
M.state(dysk=DYSK)                 що зараз у базі
M.tests(DYSK)                      прогін тестів
```

**Де результати:**

```
Мій диск/                          (на компʼютері G:\Мій диск)
├─ 0 Cases/                        ← справи: картка + протокол
│   ├─ UA-2026-10-02-004417-a 41234567/
│   │   ├─ Службова_картка_UA-2026-10-02-004417-a.docx
│   │   ├─ 01_Протокол….pdf        документи самого рішення замовника
│   │   └─ manifest.json
│   └─ UA-2026-10-02-004417-a 41234567 (2)/   друге рішення щодо того
│                                             самого учасника (інший лот)
└─ TenderWin/
    ├─ tenderwin_lead_mail.db      база: компанії, події, листи
    ├─ vyhid_lystiv/
    │   ├─ eml/                    готові листи (.eml, .txt, .html)
    │   ├─ kartky/<дата>/          робочі картки закупівель (.docx)
    │   └─ zvit_<прогін>.csv       звіт прогону
    └─ Службові картки/<дата>/
        └─ _ПЕРЕЛІК_<прогін>.xlsx  ← з нього відбирають справи
```

Теку справ можна змінити в клітинці 5: `M.CASES_DIR = "/content/drive/MyDrive/…"`.
Порожньо — «0 Cases» у корені «Мого диска».

**Лист V9 = V8 з правками власника:**

- після «що доцільно робити далі» — крапка (у V6, з яким пішов прогін 02.10, її не було);
- «Я зіставлю те, що написав Замовник у рішенні, з вимогами тендерної
  документації, документами Вашої тендерної пропозиції та практикою АМКУ.
  Якщо підстав для скарги немає, напишу про це прямо.»;
- «Якщо підстави для скарги є, то складеного мною аналізу зазвичай Вам буде
  достатньо, щоб самостійно подати скаргу в АМКУ, не витрачаючи зайвих
  коштів на юридичний супровід.»;
- замість «Якщо питання актуальне — просто відповідайте на цей лист.» —
  «Побачити, як виглядає мій аналіз, Ви можете тут: tenderwin.in.ua»
  (посилання задає `ANALYSIS_EXAMPLE_URL`);
- підпис без посилань: «З повагою, / Віталій Щасливий / радник з публічних
  закупівель / +380 800 357 135».

V8 та старіші версії не змінювались: правка тексту — нова версія.

## 7. Безпека

Секретів у коді немає. Токен Gmail береться з Colab Secrets
(`GMAIL_OAUTH_JSON`) або з файла `.gmail_token.json` у теці бази — у
репозиторій він не потрапляє і потрапити не повинен.

У `TEST_RECIPIENTS` — 16 ваших скриньок. Це єдині адреси, на які код може
доставити лист; інше блокує тригер бази.

**Що не класти в репозиторій:** `.gmail_token.json`, `tenderwin_lead_mail.db`,
`leads.db`, теку `vyhid_lystiv`, теку `Службові картки`, теку `0 Cases`.
