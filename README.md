# TenderWin Lead & Mail 1.5.0 — повний пакет

**Зібрано:** 08.10.2026 · **Режим:** БОЙОВИЙ (`LIVE`, листи клієнтам) або TEST · **Чинний лист:** `V10_OWNER` · **Ноутбук:** 1.5.0
**Схема бази:** 2 · **Python:** 3.10+

Пакет самодостатній: цього набору достатньо, щоб покласти його в репозиторій

## 1. Що це за інструмент

Шукає відхилення учасників у Prozorro за поточну добу, складає один перший
лист на компанію, робить робочу картку закупівлі, а з версії 1.3.0 — ще й
**службову картку відхилення з протоколом рішення замовника**. З версії
1.4.0 картка і протокол лягають у `Мій диск/0 Cases/<ID закупівлі> <ЄДРПОУ>`
(на компʼютері `G:\Мій диск\0 Cases`).

З версії 1.5.0 скрипт **бойовий**: у режимі `LIVE` лист іде на адресу самої
компанії з Prozorro.

**Чотири гарантії, закладені в код:**

1. У розсилку потрапляють лише події вікна прогону.
2. Одна компанія — один **бойовий** перший лист. Назавжди. Усі листи до
   08.10.2026 були тестовими і бойового листа не займають. Компанію блокує
   лише бойовий лист у черзі, надісланий або з невідомим станом; скасований
   чи невдалий — ні.
3. Лист іде лише туди, куди дозволяє режим, і це перевіряє тригер бази, а не
   лише код: `TEST` — тільки на `TEST_RECIPIENTS`; `LIVE` — тільки на адресу
   компанії з Prozorro.
4. Завантажуються **лише документи самого рішення** замовника. Документи
   пропозиції і тендерна документація — ні.

## 3. Порядок запуску в Colab

1. Робоча тека — **`1 Lead&Mail generator`** у корені «Мого диска» (назва
   задається рядком `РОБОЧА_ТЕКА` у клітинці 2). У ній — чотири файли з
   розділу 2.1. Старі файли замінювати («Замінити наявний файл»), а не
   «Зберегти обидва». Клітинка 4 перевіряє версії і зупиняється, якщо
   на Диску лишився старий скрипт.
2. Ноутбук — туди ж, відкрити в Colab.
   Відкривати саме `TenderWin_Lead_Mail_v1.5.ipynb` — старіші ноутбуки
   або шукають теку `TENDERWIN`, або працюють лише в тестовому режимі.
   **Перший запуск у новій теці:** клітинка 2 копіює з попередньої теки
   `TENDERWIN` базу `tenderwin_lead_mail.db` (кому вже писали), `leads.db` і
   `.gmail_token.json` — **один раз**: після цього в робочій теці лежить
   позначка `.перенесено_з_попередньої_теки.json`, і більше нічого не
   копіюється (зникла база → СТОП, а не підстановка старої копії). Копіювання
   йде через тимчасовий файл: обрив не лишає напівбази. У `TENDERWIN` нічого
   не видаляється і не змінюється. Далі запускати лише з нової теки: якщо в
   `TENDERWIN` зʼявляться нові листи, клітинка 2 попередить.
3. Клітинки згори вниз: 1 → 2 → 3 → 4 → 5 → 6 (сухий прогін) → 7 (відправка).
   Клітинка 5 ставить `M.MODE = "LIVE"` — бойовий режим.
4. Перед відправкою прочитати кілька листів у `vyhid_lystiv/eml` (поруч із
   кожним лежить `.html` — лист очима клієнта, а в `.txt` — адреса компанії).
5. **Клітинка 7 у бойовому режимі** надсилає клієнтам одразу, без запитань.
   «Виконати всі» розішле листи відразу після складання — щоб переглянути
   листи, виконуйте клітинки по одній.
   За один запуск — до `M.MAX_SENDS_PER_RUN` листів (25) з паузою 2–3 хв;
   якщо в черзі лишились листи, запустіть клітинку 7 ще раз. Черга живе
   один день: завтрашній прогін складає листи заново.
6. Клітинка 8 (`M.kartky`) потрібна лише тоді, коли крок карток обірвався
   або треба зібрати картки за інший день.

**Команди:**

```
M.setup(DYSK)                      база, токен, перевірки — раз за сеанс
M.go(dysk=DYSK)                    сухий прогін: пошук, листи, картки
M.kartky(dysk=DYSK)                службові картки ще раз
M.kartky(day="2026-10-02", …)      картки за конкретний день
M.send(dysk=DYSK)                  відправка на ваші тестові скриньки
M.state(dysk=DYSK)                 що зараз у базі
клітинка 9                         прогін тестів із testy/
```

**Де результати:**

```
Мій диск/                          (на компʼютері G:\Мій диск)
├─ 0 Cases/                        ← справи: картка + протокол
│   ├─ UA-2026-10-02-004417-a 41234567/
│   │   ├─ Службова_картка_UA-2026-10-02-004417-a.docx
│   │   ├─ 01_Протокол….pdf        документи самого рішення замовника
│   │   └─ manifest.json
│   └─ UA-2026-10-02-004417-a 41234567 (2)/   друге рішення щодо того
│                                             самого учасника (інший лот)
├─ 1 Lead&Mail generator/        ← робоча тека: скрипти, ноутбук, база
│   ├─ tenderwin_lead_mail.db      база: компанії, події, листи
│   ├─ leads.db, .gmail_token.json історія попереднього рушія, токен пошти
│   ├─ vyhid_lystiv/
│   │   ├─ eml/                    готові листи (.eml, .txt, .html)
│   │   ├─ kartky/<дата>/          робочі картки закупівель (.docx)
│   │   └─ zvit_<прогін>.csv       звіт прогону
│   └─ Службові картки/<дата>/
│       └─ _ПЕРЕЛІК_<прогін>.xlsx  ← з нього відбирають справи
└─ TENDERWIN/                      попередня робоча тека — резервна копія,
                                   звідси один раз скопійовано базу й токен
```

Теку справ можна змінити в клітинці 5: `M.CASES_DIR = "/content/drive/MyDrive/…"`.
Порожньо — «0 Cases» у корені «Мого диска».

## 7. Безпека

Секретів у коді немає. Токен Gmail береться з Colab Secrets
(`GMAIL_OAUTH_JSON`) або з файла `.gmail_token.json` у теці бази — у
репозиторій він не потрапляє і потрапити не повинен.

У режимі `TEST` лист може піти лише на 16 ваших скриньок із `TEST_RECIPIENTS`.
У режимі `LIVE` — лише на адресу самої компанії з Prozorro. Обидва правила
перевіряє тригер бази. Бойову відправку робить клітинка 7 — одразу, без запитань.

**Що не класти в репозиторій:** `.gmail_token.json`, `tenderwin_lead_mail.db`,
`leads.db`, теку `vyhid_lystiv`, теку `Службові картки`, теку `0 Cases`.
